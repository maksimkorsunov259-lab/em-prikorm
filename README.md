# ЕмПрикорм

Бесплатный дневник прикорма для семьи и её врача. Автор — **Коршунов Максим Александрович**, аллерголог-иммунолог, педиатр.

Версия **1.0.27**, клинические правила **1.1**. Статическое приложение (PWA), без сервера дневников, регистрации и аналитики.

## Возможности

- Отдельные профили пациентов, продукты, приёмы пищи, отказы и наблюдения о симптомах.
- Каталог из 188 продуктов с иллюстрациями, поиском, фильтром «Богатые железом» и отдельными группами аллергенов.
- План врача, памятки о безопасной подаче и действиях при реакции.
- Цветной календарь последних семи дней, отчёт для врача, печать / PDF.
- Локальное сохранение, резервная копия всех пациентов, добавление или замена данных из копии.
- Работа без сети после первого успешного открытия и подготовки приложения.
- Установка на Android и iOS с иконкой автора без внешнего белого поля.

Приложение фиксирует сведения семьи, не диагностирует аллергию, не определяет безопасную дозу и не подтверждает переносимость. Сведения об одном продукте не переносятся на другие виды рыбы или орехов. При рисках, симптомах и ограничениях действует индивидуальный план врача. Приложение не проходило независимую клиническую валидацию.

## Публикация на GitHub Pages

Проект подготовлен для отдельного репозитория **maksimkorsunov259-lab/em-prikorm**. Планируемый адрес после публикации: `https://maksimkorsunov259-lab.github.io/em-prikorm/`. Само наличие этого адреса в документации не означает, что сайт опубликован.

1. Создайте публичный репозиторий `em-prikorm`. При первой загрузке удобнее оставить его пустым: без README, лицензии и .gitignore.
2. Загрузите содержимое проекта в ветку `main`. `index.html`, `manifest.webmanifest`, `sw.js` и папка `assets` должны лежать в корне репозитория, а не внутри дополнительной папки. Для загрузки архив сначала распакуйте.
3. В **Settings → Pages → Build and deployment** выберите **Deploy from a branch**, затем **main**, **/ (root)** и **Save**.
4. Дождитесь завершения публикации в Actions / Pages. Откройте опубликованный адрес по HTTPS, затем «Памятка → Данные и установка» и дождитесь сообщения о готовности без сети.
5. Android: Chrome → меню → «Установить приложение». iPhone/iPad: Safari → «Поделиться» → «На экран Домой».

Для push из подготовленного локального проекта:

```sh
git remote add origin https://github.com/maksimkorsunov259-lab/em-prikorm.git
git push -u origin main
```

Если `origin` уже существует, повторно добавлять его не нужно. Не заменяйте существующие приложения этим проектом. У ЕмПрикорм отдельные manifest ID `/em-prikorm/`, scope, service worker и база IndexedDB `em-prikorm.diary.v1`. При смене имени репозитория или домена требуется проверить manifest и перенос данных: браузерные данные не перемещаются автоматически.

## Данные и резервные копии

Записи и фото сохраняются в IndexedDB выбранного браузера на устройстве. Они не отправляются автору, GitHub или врачу. GitHub Pages обслуживает файлы сайта; внешние ссылки открываются отдельно. Между устройствами и приложениями нет синхронизации.

Перед очисткой браузера, сменой устройства или переустановкой скачайте копию в разделе «Данные и установка». JSON-копия содержит медицинские сведения **без шифрования**; храните её приватно. Не добавляйте копии, отчёты и реальные фотографии пациентов в публичный репозиторий. Фото в отчёт включаются только после отдельной отметки.

При ошибке чтения или записи редактирование останавливается. При доступных данных можно скачать восстановительную копию. Ошибка другой вкладки не приводит к перезаписи её изменений: скачайте несохранённые данные, затем перезагрузите вкладку. Копия восстановления с неподдерживаемой схемой предназначена для сохранения исходных данных и может требовать технической помощи перед импортом.

Ограничения версии: до 100 пациентов, до 20 000 записей еды и 20 000 наблюдений на профиль, фото PNG/JPEG/WebP до 8 МБ, импорт файла до 64 МБ. Практический объём ограничен квотой браузера. Регулярно скачивайте резервные копии и избегайте накопления больших фото. Очистка данных сайта удаляет локальные дневники.

## Локальный запуск и проверки

Для самого приложения зависимости и сборка не нужны. Для запуска требуется Python 3, для проверок модели — Node.js 22+; для браузерных проверок — Python Playwright и Chromium.

Из родительской папки проекта:

```sh
python3 -m http.server 8040 --bind 127.0.0.1
```

Адрес для локальной разработки: `http://127.0.0.1:8040/em-prikorm/`. Открытие через `file://` не поддерживает установку и полноценное сохранение. На реальном устройстве используйте HTTPS-сайт.

В папке проекта:

```sh
node --test tests/*.test.cjs
python3 tests/browser_flows.py
python3 tests/browser_edges.py
python3 tests/browser_updates.py
python3 tests/browser_nutrition_install.py
```

Браузерные тесты используют только искусственные данные и временные профили. По умолчанию Chromium ищется в `/usr/bin/chromium`; переменные `CHROMIUM_PATH` и `APP_URL` позволяют изменить путь и тестовый адрес. Проверяются сохранение, профили, резервные копии, срочная помощь, отчёты, защита от HTML-вставки, 84 сочетания экранов и ширины, офлайн-доступ и устанавливаемость в Chromium. Физические Android/iOS-устройства этим набором не проверяются.

После изменения файлов приложения:

```sh
python3 tools/build_sw.py
```

Команда обновляет стили автономного отчёта и хеш офлайн-кеша. Закоммитьте изменённые файлы вместе. Готовое обновление появляется в плашке «Доступна новая версия» на любом экране и в «Данные и установка». Кнопка «Обновить приложение» перезапускает приложение после проверки сохранения. Незавершённую форму или загрузку фото нужно сначала закончить; сохранённые дневники остаются в IndexedDB. Перед крупным обновлением сохраните резервную копию.

Внутри приложения и в манифесте используются новые файлы `icon-rounded-*`, чтобы браузер не переиспользовал прежние иконки по тому же адресу. ## Если обновление не появляется

В «Памятка → Данные и установка» постоянно доступна кнопка «Проверить обновления». Она сообщает о готовом обновлении, отсутствии новой версии, отсутствии сети или ошибке загрузки. Установка, как и раньше, требует отдельного подтверждения и ждёт сохранения дневника.

Для старой версии, где этой кнопки ещё нет, откройте `https://maksimkorsunov259-lab.github.io/em-prikorm/update.html` в том же браузере. Сначала сохраните записи и закройте другие окна ЕмПрикорм. Страница не читает и не удаляет IndexedDB, локальное хранилище или дневники, не отменяет регистрации других приложений. Она проверяет обновление только в области ЕмПрикорм и применяет его после явного подтверждения пользователя. `update.html` и `update-recovery.js` специально не включены в автономный кэш: для восстановления нужна сеть.

Проверка: `python tests/browser_update_recovery.py`. Тест поднимает отдельный сервер, проверяет ручной поиск, отказ сети/сервера, обновление через отдельную страницу, точное сохранение всех данных коллекции, окно «О приложении» и автономную работу после обновления. Недоступность страницы `update.html` с ошибкой 404 указывает, что новые файлы ещё не опубликованы по этому адресу; кнопкой внутри старой версии это исправить нельзя.

## Отметки продуктов · 1.0.14

В каталоге, фильтрах, списке аллергенов и карточке продукта показаны знаки с текстовым пояснением: зелёная галочка — фактическое употребление с завершённым наблюдением без отмеченных симптомов либо с исключённой врачом связью прежних симптомов; красный восклицательный знак — связанные симптомы или действующее ограничение; жёлтый круг — незавершённое/неуточнённое наблюдение; точка — нет записи об употреблении. Отказ и предложение еды не засчитываются. Указана дата последней записи. Для подходящих продуктов без ограничений после недели без записей доступно напоминание о регулярном употреблении, а не автоматическое назначение пробы.

В карточке есть «Уточнить отметку после консультации». Можно внести дату, врача и содержание заключения об исключении связи с конкретным продуктом либо вернуться к отметке по дневнику. Уточнение относится к сохранённым версиям связанных наблюдений и приёмов: новое наблюдение или изменение связанной записи снова требует оценки. Действующие ограничения и незавершённое наблюдение не снимаются. Исходные симптомы сохраняются; заключение отдельно включается в отчёт и резервную копию. Сведения изолированы по пациентам. Старые копии без `foodReviews` получают пустой список при проверке.

Проверки: `node --test tests/*.cjs`, `tests/browser_food_marks.py`. В том числе отдельные ингредиенты блюда, возврат к исходной отметке, новые/изменённые симптомы, старые копии, перезагрузка и работа без сети.

## Напоминания на странице «Сегодня» · 1.0.15

Блок «Сохраняем продукты в рационе» появляется для выбранного ребёнка, когда последнее записанное употребление подходящего продукта было больше семи календарных дней назад. Используются те же условия, что в карточке продукта: завершённое наблюдение, зелёная отметка, отсутствие ограничений и факторов, требующих индивидуального плана. Специи, масла, прочие продукты (в том числе мёд) и молочное вскармливание не включаются. Ровно семь дней ещё не запускают напоминание. Первые три позиции показаны сразу, остальные раскрываются; порядок — от наиболее давней записи.

Кнопка «Записать употребление» открывает обычную форму с выбранным продуктом. Новая фактическая запись пересчитывает список; отказ или предложение не считаются употреблением. Напоминания видны при открытии приложения и работают без сети. Уведомления на заблокированный телефон не отправляются. Текст сохраняет практический ориентир раз в неделю без гарантии профилактики аллергии.

В окне «Если ребёнок подавился» кнопка «Вернуться» находится сверху справа и остаётся доступной при прокрутке. Размер и оформление согласованы с другими окнами. При последующем автоматическом показе срочной помощи восстанавливается прежняя кнопка под инструкциями.

## Каталог и памятка · 1.0.17

В «Продуктах» оставлены фильтры «Все», «Богатые железом», «В дневнике»; отдельный раздел «Аллергены» сохранён. Икра имеет собственный ключ `fishRoe` и группу «Рыбная икра»: её употребление, симптомы, назначения и отчёт учитываются отдельно от мяса рыбы. Идентификатор `fish-roe`, изображения и старые записи сохранены; переноса переносимости между икрой и рыбой нет.

Для новых приёмов доступны «Ел», «Отказался», «Приёма не было». Старое `offered` остаётся допустимым в хранилище и копиях. При редактировании такой записи нужно явно уточнить исход; она не превращается автоматически в съеденный продукт. Под полем наблюдения и в памятке добавлен период 3–5 дней после знакомства с новым продуктом для отслеживания возможных отсроченных изменений. Это не таймер, не срок исключения аллергии и не повод ждать при острых симптомах.

Пункт готовности к глотанию дополнен угасанием выталкивающего рефлекса языка. C28 расширен на молоко и/или яйцо с индивидуальным диагностическим планом и полноценной заменой питания; область применимости прежних источников указана отдельно. Из памятки убрана кнопка отчёта, доступ из дневника сохранён.

## Возврат между экранами · 1.0.21

Кнопки возврата используют стрелку и название страницы назначения. Окна информации и помощи называют экран, который остаётся под ними; их закрытие сохраняет поля, фокус и прокрутку. Возврат из вложенных разделов учитывает источник перехода. Выход из несохранённой формы требует подтверждения. История переходов хранится только в памяти интерфейса и не меняет медицинские записи.

Проверка: `APP_URL=http://127.0.0.1:8055/em-prikorm/ python tests/browser_returns.py`. Дополнительно проверены прежние сценарии навигации и окон помощи.
